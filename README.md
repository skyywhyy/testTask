# Тестовое задание

Динамическая библиотека обработки строк и две программы, обменивающиеся данными
через TCP-сокеты. Программа №1 принимает ввод пользователя в одном потоке,
обрабатывает его во втором через общий буфер и передаёт рассчитанную сумму
Программе №2, которая проверяет её и печатает результат. Обе программы
переживают запуск в любом порядке, а также остановку и перезапуск партнёра.

## Требования

- Linux
- gcc с поддержкой C++17 (v 13.3 +)
- CMake 3.16 или новее


## Структура проекта

```
library/    динамическая библиотека libprocessing.so — три функции из задания
program1/   ввод пользователя, два потока, общий буфер, TCP-клиент
program2/   TCP-сервер, проверка полученных сумм
common/     общие сетевые настройки (хост и порт)
tests/      автоматические тесты, запускаются через ctest
```

## Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

При необходимости проект можно установить в произвольный каталог:

```bash
cmake --install build --prefix ./install
```

## Запуск

Программы запускаются в двух терминалах:

```bash
./build/bin/program2
```

```bash
./build/bin/program1
```

Порядок запуска не важен — если партнёр ещё не поднят, программа дождётся его.
Программа №2 слушает `127.0.0.1:5050`.

Программа №1 завершается по команде `exit`, по концу ввода или по `Ctrl+C`,
Программа №2 — по `Ctrl+C`.

## Пример работы

Программа №1 принимает строку из цифр длиной не более 64 символов:

```
Enter 1 to 64 digits or 'exit':
9999999999995555
Processed: 9999999999995555
Sum: 128
Sum sent: 128
12345
Processed: 5KB3KB1
Sum: 9
Sum sent: 9
abc
Invalid input: enter 1 to 64 digits
exit
```

Программа №2 в это же время выводит:

```
Server is listening on 127.0.0.1:5050
Client connected.
Received valid sum: 128
Error: sum does not satisfy the condition
Client disconnected. Waiting for a new connection...
```

```bash
cd build && ctest --output-on-failure
```

## Архитектура

### Библиотека

`library/include/processing/processing.hpp` объявляет три функции задания:

- `transform` — сортирует строку по убыванию и заменяет каждую чётную цифру на
  «KB». Ничего не возвращает. Проверка ввода намеренно оставлена вызывающей
  стороне: по заданию это задача первого потока Программы №1.
- `calculate_sum` — возвращает сумму всех цифр строки.
- `is_valid_sum` — возвращает «истину», если строка длиннее двух символов и
  записанное в ней число кратно 32.

### Программа №1

Поток ввода читает строку, проверяет, что она состоит только из цифр и не длиннее
64 символов, передаёт её в `transform` и кладёт результат в общий буфер.

Рабочий поток забирает значение, печатает его,
считает сумму через `calculate_sum` и отправляет её Программе №2.

Потоки синхронизированы через `std::condition_variable`.

Рабочий поток всегда сначала опустошает буфер и только потом занимается
отправкой, поэтому недоступность Программы №2 никогда не блокирует ввод.
Неотправленные суммы копятся в очереди (до 1024 значений, при переполнении
вытесняются самые старые) и уходят при первой возможности.

### Программа №2

Неблокирующий `accept` с `poll` принимает одного клиента за раз, читает строки,
передаёт их в `is_valid_sum` и печатает результат. После обрыва соединения
возвращается к ожиданию нового клиента.

### Протокол

Программа №1 отправляет сумму десятичным числом, завершая строку `\n`.
Программа №2 отвечает `OK\n`. Подтверждение нужно, чтобы Программа №1 не считала
значение доставленным, пока оно действительно не обработано.

## Поведение при обрыве связи

Если Программа №2 не запущена или остановлена, Программа №1 сообщает об этом один
раз и продолжает принимать ввод:


Накопленные за время недоступности суммы отправляются в исходном порядке.

Если останавливается Программа №1, Программа №2 печатает
`Client disconnected. Waiting for a new connection...` и ждёт нового подключения.

Задержка подтверждения не считается потерей связи: пока соединение живо,
Программа №1 продолжает ждать ответ, а не отправляет значение повторно — иначе
Программа №2 сообщила бы об одной и той же сумме дважды. Если ответа нет
слишком долго, соединение всё же считается мёртвым и значение отправляется
заново.

## Условие третьей функции

Формулировка задания про третью функцию неоднозначна: «если оно больше 2-ух
символов и, если оно кратно 32». Уточнение в скобках относит кратность к
значению суммы, а не к длине строки, поэтому реализовано так: строка длиннее
двух символов **и** записанное в ней число кратно 32.

Отсюда следует, что «истину» дают далеко не любые данные. Сумма считается по
отдельным цифрам, максимум для 64 символов — 576, а условие «больше двух
символов» отсекает всё меньше 100. Подходящих значений пятнадцать: 128, 160,
192, 224, 256, 288, 320, 352, 384, 416, 448, 480, 512, 544 и 576. Сообщение
`Error: sum does not satisfy the condition` для большинства вводов — ожидаемый
результат.

## Известные ограничения

- Хост и порт заданы в `common/include/common/network_config.hpp` и не
  настраиваются аргументами командной строки.
- Программа №2 обслуживает одно подключение одновременно.
- Очередь неотправленных сумм ограничена 1024 значениями; при переполнении
  вытесняются самые старые, о чём выводится предупреждение.
- Если Программа №2 завершается ровно между обработкой значения и доставкой
  подтверждения, значение может быть отправлено повторно и показано дважды.
